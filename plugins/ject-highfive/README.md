# ject-highfive

참여 중인 팀 프로젝트(밴드 합동공연 앱의 Spring Boot 백엔드)에서만 쓰는 스킬입니다.
다른 프로젝트에서는 쓸 일이 없으므로 그 레포에만 프로젝트 범위로 설치합니다.

```
/plugin install ject-highfive@namyoungjun-plugins --scope project
```

## 포함된 것

- `skills/ject-highfive-review` - PR을 올리기 전에 내 변경 사항을 리뷰 (`/ject-highfive:ject-highfive-review`)

## 리뷰 스킬을 이렇게 만든 이유

**내장 `/code-review` 위에 얹었다.** 버그 찾기는 내장 리뷰가 잘한다. 이 스킬은 그 결과를 받고, 내장 리뷰가
모르는 두 가지를 더한다.

| 단계 | 무엇을 잡나 |
|---|---|
| 기계 검사 (Spotless, Checkstyle, 테스트) | 포맷, 컨벤션 위반, 깨진 테스트 |
| 내장 `/code-review` | 로직 오류 같은 일반적인 버그 |
| 기획서 대조 | 기능명세서·API 명세·ERD와 구현이 다른 곳, 빠진 요구사항 |
| 팀 규칙 | 엔티티·DTO·응답 형식·권한 확인 같은 팀 컨벤션 위반 |

결과는 `[심각도] 파일:줄 - 문제 - 제안 (근거)` 한 목록으로 합친다. 근거를 붙여서 일반 버그인지, 명세나
팀 규칙에서 나온 지적인지 바로 구분할 수 있게 했다.

**CI가 아니라 개인 리뷰로 했다.** GitHub Actions에 붙이면 팀원 모두의 PR에 돈다. AI 리뷰를 쓸지는 각자
정할 일이라, 내 PR을 올리기 전에 내 로컬에서만 돌린다.

**리뷰만 하고 고치지 않는다.** 지적이 틀릴 수 있으니 무엇을 고칠지는 사람이 정한다.
